What Is a Packet?

Data sent over a network is broken down into smaller units called packets. Each packet has three parts:

A packet = Header + Payload + Trailer

1. Header

Destination address, packet number, originator's address.

2. Payload

The actual data being transmitted.

3. Trailer

Error-checking data (e.g. checksum) and end-of-packet marker.

2.1 · Types & Methods

Packet Switching Process

  1. Data is broken down into packets.
  2. Each packet is sent individually across the network.
  3. Routers control the route — packets may take different paths.
  4. Packets may arrive out of order at the destination.
  5. Once the last packet arrives, they are reordered using packet numbers.
Key point: because each packet finds its own route, the network keeps working even if one path fails.
Each packet is routed independently — different packets, different paths

Transmission Directions

🔽 Simplex

Data travels in one direction only.

Example: computer → monitor (display only).

⇄ Half-Duplex

Both directions, but only one at a time.

Example: walkie-talkie — "over" to switch.

⇄ Full-Duplex

Both directions simultaneously.

Example: telephone call — both speak at once.

ModeDirection of dataExample
SimplexOne way onlyComputer → monitor, keyboard → computer
Half-DuplexBoth ways, one at a timeWalkie-talkie, Wi-Fi
Full-DuplexBoth ways, simultaneouslyTelephone call, video call

Suitability Scenarios

Exam questions love giving you a scenario and asking which method to use — and why.

ScenarioBest methodWhy
Internal computer buses (CPU → RAM) Parallel High speed is needed over very short distances — skewing is not a problem.
Printer / external drive over a distance Serial Longer cables — parallel bits would skew; serial stays accurate.
Internet connection Serial Data travels long distances; serial avoids data skewing.
Video conferencing Full-Duplex Instant two-way communication is vital — both sides talk at once.
Keyboard → computer Simplex Data only ever flows one way.
Walkie-talkie radio Half-Duplex Both people need to speak, but not at the same time.
Exam tip: always justify your choice — "parallel is fast but only over short distances" and "serial is reliable over long distances" are the key phrases.

Universal Serial Bus (USB)

USB is an asynchronous serial data transmission method — data is sent one bit at a time over a single connection.

✅ Benefits

  • Automatically detects connected devices
  • Connector fits only one way — prevents incorrect connection
  • An industry standard — works across many devices
  • Supports different transmission speeds
  • Can power devices (charge phones, run drives)

⚠ Drawbacks

  • Cable length limited to ~5 metres
  • Transmission speed is slower than internal parallel buses
USB connects computers to external devices using serial transmission

Any three of: destination address, packet number, originator's (sender's) address.

📝 Q2. Why is parallel transmission unsuitable for long distances?

Over long distances the bits can become unsynchronised / skewed — they arrive at slightly different times, corrupting the data. Serial is used instead.

📝 Q3. A walkie-talkie uses which transmission direction?

Half-duplex — data flows both ways but only one direction at a time ("over"!).

Why Do Errors Occur?

🌩️ Causes of Errors

During transmission, data can be corrupted by:

  • Electrical interference (noise) — nearby signals, power lines
  • Distortion of the signal
  • Wear and tear on cables
sent: 0 1 1 0 0 1 0 1
got:  0 1 1 1 0 1 0 1  ← one bit flipped!
Key idea: a flipped bit (0 → 1 or 1 → 0) changes the value — error detection methods catch this.

📋 Three Types of Data Error

ErrorMeaningExample
Data lossSome data never arrives10110 → 100
Data gainExtra (unwanted) data arrives10110 → 101100
Data changeA bit arrives with a different value10110 → 10010

🔎 The Goal

Error detection methods let the receiver notice that data was corrupted, and often request a resend.

Parity Checks (Odd and Even)

A parity bit is added to a byte so that the total number of 1s is either even (even parity) or odd (odd parity). Both sides agree the rule in advance.

Worked Example — Even parity

Byte 1011001 → add even parity bit

// count the 1s in 1011001 1 0 1 1 0 0 1  =  4 ones // 4 is even → parity bit = 0 sent: 1011001 0  (still 4 ones, even ✓)
1011001 0
data (7 bits)parity
Worked Example — Odd parity

Byte 1011001 → add odd parity bit

// count the 1s in 1011001 1 0 1 1 0 0 1  =  4 ones // 4 is even, we need ODD → parity bit = 1 sent: 1011001 1  (5 ones, odd ✓)
1011001 1
data (7 bits)parity
💡
Exam Tip: Parity checks cannot detect if an even number of bits (e.g. two bits) flip during transmission — the count of 1s stays the same.

Parity Blocks

A parity block arranges several bytes in a grid with parity bits across each row and down each column. This can locate and correct a single flipped bit.

b1b2b3b4b5b6b7par
Row 110110010
Row 201011000
Row 311011010
Row 400110110
par00010010
Row 3 and column b4 both fail → error is at their intersection (corrected by flipping it back)
Advantage: parity blocks can detect AND correct a single error — better than a single parity bit.

🔍 How It Works

  1. Data is arranged in rows of bytes, each with a row parity bit.
  2. A final column parity row is calculated down each column.
  3. On receipt, both are recalculated.
  4. A failing row and a failing column cross at the error cell.
  5. The bit is flipped back — the error is corrected.

📝 Example above

Row 3 parity fails and column b4 parity fails → the error is at (Row 3, b4). Flip that bit: 1 → 0, and the data is correct again.

Checksum

🧮 What Is a Checksum?

A checksum is a value calculated from a block of data using an algorithm, before transmission. It is sent with the data.

⚙️ How It Works

  1. Sender calculates checksum from the data.
  2. Data + checksum are sent together.
  3. Receiver recalculates the checksum from the data it received.
  4. If it matches → no error.
  5. If it doesn't match → error → retransmission requested.
Checksum: compare calculated vs received → match = OK, mismatch = resend
Note: checksums detect errors in a block of data; they are used in protocols like TCP/IP.

Echo Check

🔁 How It Works

  1. Data is sent to the receiver.
  2. The receiver immediately echoes the data back to the sender.
  3. The sender compares the echoed data with the original.
  4. If they differ → an error occurred → resend.
Drawback: if an error is found, the sender doesn't know whether it happened on the way there or on the way back.
The receiver echoes the data so the sender can check it

Check Digits

Important: check digits detect human data-entry errors (typing mistakes), not transmission errors. They are used in barcodes and ISBNs.

📊 How It Works

  1. The final digit is calculated from the previous digits using an algorithm (e.g. Modulo 11 or Modulo 10).
  2. When the number is entered, the check digit is recalculated.
  3. If it doesn't match the entered one → the entry is rejected.

📦 Where They're Used

  • ISBN — book numbers (Modulo 11)
  • Barcodes — products in shops (Modulo 10)
  • Credit card numbers
Worked Example — catch a typo

ISBN: 978-0-521-88418-3

// digits + check digit 9 7 8 0 5 2 1 8 8 4 1 8  3 // algorithm recalculates the last digit // typed 9780521884187 → check fails → rejected calculated check digit = 3 entered check digit    = 7  ❌ mismatch

A wrong check digit means the number was entered incorrectly

💡
Exam Tip: check digit → detects human entry errors. Checksum → detects transmission errors. Don't mix them up!

Automatic Repeat Query (ARQ)

✅ Acknowledgements

  • Positive ACK — data received OK, no need to resend.
  • Negative ACK (NAK) — error detected, request resend.

⏱️ Timeout

If the sender doesn't receive an acknowledgement within a set time, it automatically resends the data.

ARQ: ACK / NAK + timeout → automatic retransmission
Combination: ARQ is often used with other error-detection methods (parity, checksum) that trigger the NAK.

Recap — Practice Questions

Try each question, then reveal the answer.

📝 Q1. Calculate the even parity bit for 1100110

1100110 has four 1s — already even → parity bit = 0. Sent as 1100110 0.

📝 Q2. Explain the difference between a check digit and a checksum

A check digit is a single value calculated from the digits of a number to catch human entry errors (ISBN, barcodes). A checksum is calculated from a block of transmitted data to catch transmission errors.

📝 Q3. What does ARQ stand for and what happens on a timeout?

Automatic Repeat Query. If no acknowledgement (ACK) is received within the set time, the sender automatically resends the data.

📖 Revision tip: know which method catches what — parity = single-bit flips, checksum = block errors, echo = sends data back, ARQ = resends on no-ACK.

The Need for Encryption

🔒 Why Encrypt?

Encryption scrambles data into an unreadable format called ciphertext, so that if it is intercepted during transmission, unauthorized users cannot understand it.

  • Protects passwords, card numbers, personal data
  • Keeps data safe even if a hacker intercepts it
  • Essential for online banking, shopping, messaging

📄 Plaintext

The original, readable data before encryption.

Hello! Secret: 1234

🔐 Ciphertext

The encrypted, unreadable data after encryption.

X8k$#9Lm@2!qQz
Plaintext → encrypt → ciphertext → transmit → decrypt → plaintext

Symmetric Encryption

🗝️ Same Key Both Ways

Symmetric encryption uses the same secret key to encrypt and decrypt the data.

⚠ The Problem

The key itself must be shared securely between sender and receiver. If the key is intercepted, the security is compromised — anyone with the key can decrypt the data.

Example: Wi-Fi networks (WPA2), file encryption — fast, but key-sharing is the weak point.
Symmetric: one key does both jobs

Asymmetric Encryption

🔑 A Key Pair

Asymmetric encryption uses a mathematically linked key pair:

  • Public Key — kept open, known to everyone
  • Private Key — kept secret, only the owner knows it

🛡️ The Process

  1. The sender encrypts data using the receiver's public key.
  2. The data is transmitted as ciphertext.
  3. Only the receiver's private key can decrypt it.
Why secure: the private key is never shared or transmitted — it cannot be intercepted.
Asymmetric: encrypt with receiver's public key, decrypt with receiver's private key

Recap — Practice Questions

Try each question, then reveal the answer.

📝 Q1. Why is asymmetric encryption more secure than symmetric?

In asymmetric encryption the private key is never shared or transmitted — it cannot be intercepted. Symmetric encryption requires the single secret key to be shared, which is the weak point.

📝 Q2. Define plaintext and ciphertext

Plaintext = the original, readable data. Ciphertext = the encrypted, unreadable data produced by encryption.

📝 Q3. In asymmetric encryption, which key does the sender use to encrypt?

The receiver's public key. Only the receiver's private key can decrypt the data.

📖 Revision tip: remember the golden rule — public key encrypts, private key decrypts, and the private key is never shared.
