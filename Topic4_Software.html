Functions of an Operating System (Part 1)

The OS has 9 required functions. Here are the first five:

1. 📁 Managing files

Organising, naming, storing and retrieving data on storage devices.

2. 🚨 Handling interrupts

Responding to signals from hardware or software that need immediate attention.

3. 🖥️ Providing an interface

A GUI (graphical) or command-line interface for user interaction.

4. 🔌 Managing peripherals & drivers

Allowing hardware devices to communicate with the CPU via drivers.

5. 🧠 Managing memory

Allocating RAM space to running programs and processes.

💡 Worked scenario

You save a Word file: the OS manages the file (files), keeps Word running (memory), and uses the printer driver (peripherals) — several functions at once.

The Software / Hardware Relationship

Each layer runs on the layer below it

🔓 The Bootloader

The bootloader is firmware stored in ROM that loads the operating system into RAM when the computer starts.

  • Runs first — before the OS exists
  • Checks hardware (POST)
  • Transfers control to the OS

🔄 How It All Fits

  1. Hardware powers on.
  2. Firmware (bootloader) in ROM loads the OS into RAM.
  3. The OS manages hardware and provides a platform.
  4. Applications run on top of the OS.

What Is an Interrupt?

🚨 Definition

An interrupt is a signal sent to the processor that temporarily stops the normal fetch-decode-execute cycle so that a higher priority task can be dealt with immediately.

🎯 Why Interrupts Matter

  • Let hardware tell the CPU "something needs doing now"
  • CPU doesn't waste time polling (constantly checking)
  • Keeps the system responsive — e.g. keypresses handled instantly
An interrupt pauses the current work to handle something urgent

How an Interrupt Is Handled

  1. An interrupt signal is generated (by hardware or software).
  2. The current FDE cycle finishes executing its current instruction.
  3. The CPU checks the priority of the interrupt against the current task.
  4. The contents of the registers (the current state) are saved to a stack in memory.
  5. The interrupt service routine (ISR) is run to deal with the interrupt.
  6. Once the ISR is complete, the saved register contents are restored, and the original task resumes from where it left off.
The six-step interrupt handling process

Assembly Language and Assemblers

🔤 Assembly Language

A low-level language that uses mnemonics — short, memorable commands like LDA, ADD, STO — instead of binary.

  • One mnemonic ≈ one machine-code instruction
  • Still machine-specific
  • Easier for humans than raw binary

🔧 The Assembler

An assembler is the translator software that converts an assembly language program into machine code (binary) the CPU can execute directly.

Worked Example — mnemonics
; assembly program (mnemonics) LDA #10    ; load 10 into accumulator ADD #05    ; add 5 STO total  ; store result HLT        ; stop

assembler → 10110000 00001010 …

Assembler converts mnemonics into binary machine code

Compilers — How They Work

⚙️ The Process

A compiler translates the entire high-level source code into machine code all at once, before the program is run.

  • Produces a standalone executable file
  • Run once per program version

📋 Error Reporting

A compiler generates a full error report listing all errors found throughout the whole program, after scanning it completely.

Whole program → machine code → executable, then a full error report

Interpreters — How They Work

⚙️ The Process

An interpreter translates and executes high-level source code line by line, one instruction at a time.

  • Does not produce a saved executable file
  • Needs the interpreter to be present to run

📋 Error Reporting

An interpreter stops execution immediately as soon as it reaches a line containing an error, without checking the rest of the code.

Interpreter: one line at a time — stops at the first error

When to Use Each Translator

The practical development cycle: interpret while writing, compile for release

📦 For release
