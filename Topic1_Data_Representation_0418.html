Why Do Computers Use Binary?

⚡ Two Physical States

Data is processed by logic gates and stored in registers. Electronic components (transistors / switches) have only two stable states:

  • ON → high voltage → 1
  • OFF → low voltage → 0

🧠 Why Not Denary (0–9)?

Designing circuits with 10 reliable voltage levels would be hugely complex, expensive and error-prone. Two states are simple, reliable and cheap to build.

Key idea: Everything a computer stores — numbers, text, sound, images — is reduced to sequences of bits (binary digits).
A switch has exactly two states — so binary (0 / 1) is the natural choice

Golden rule: each hex digit = exactly 4 binary bits (a nibble). No division needed — just convert each digit.

Why Use Hexadecimal?

📉 Shorter & Easier to Read

A long binary string such as 1111000110101110 becomes just 4 hex digits: F1AE. Much easier for humans to read and remember.

✅ Less Error-Prone

Typing 4 hex characters is far less likely to introduce errors than typing 16 binary digits.

🌐 Real-World Uses

  • MAC addresses: 00:1A:2B:3C:4D:5E
  • IPv6 addresses: 2001:0db8:85a3::8a2e
  • HTML/CSS colours: #FF5733
  • Memory / error addresses when debugging
  • ASCII debugging: hex codes for characters
💡
Exam Tip: Be ready to identify a real-world use of hex — MAC addresses, IP (IPv6) addresses and HTML colour codes are the classic examples.

Overflow in Binary Addition

⚠ What Is Overflow?

Overflow occurs when the result of a calculation is too large to fit in the fixed number of bits available.

  • An 8-bit register can store values 0–255
  • If a sum needs a 9th bit, that bit is lost
  • The stored result is therefore incorrect
Note: overflow doesn't crash the computer — it just silently produces a wrong answer. That's why it matters!
Worked Example — overflow

11111111₂ + 00000001₂

carries → 1 1 1 1 1 1 1 1  ← carry row      1 1 1 1 1 1 1 1  (255₁₀) +  0 0 0 0 0 0 0 1  (1₁₀) ─────────────────  1 0 0 0 0 0 0 0 0  (256₁₀) // the 9th bit (the 1) cannot be stored // register keeps only: 00000000 = 0 ❌
1 000 0000
9th bit — LOST

255 + 1 should be 256, but 256 needs 9 bits → stored result 0 is wrong

💡
Exam Tip: State it clearly: "An 8-bit register can only store 0–255; overflow occurs when the sum needs a 9th bit."

Effects of Shifts

ShiftDirectionEffect on valueWhat is lostExample
Left shift by n←← Multiply by 2ⁿ Most significant bits (left end) 00010110 << 2 → 01011000 (×4)
Right shift by n→→ Divide by 2ⁿ (integer — remainder lost) Least significant bits (right end) 11001000 >> 3 → 00011001 (÷8)

📐 Rule to remember

Left shift by n = value × 2ⁿ
Right shift by n = value ÷ 2ⁿ

Shifting by 1 = ×2 or ÷2. Shifting by 2 = ×4 or ÷4. Shifting by 3 = ×8 or ÷8.

⚠ Watch out

  • Bits that "fall off" the end are lost forever
  • Left shifts can cause overflow if the MSB is lost
  • Right shifts are integer division — any remainder is discarded

Two's Complement — Negative Numbers

🎯 Why Do We Need It?

Binary can only store 0 and 1 — so how do we represent a minus sign? Two's complement is a system for storing negative integers in binary.

🔄 The Rule

To convert a positive number to its negative (two's complement) form:

  1. Write the number in binary (8 bits)
  2. Invert all the bits (0→1, 1→0)
  3. Add 1 to the result
Worked Example — +52 → −52

Convert +52 to two's complement −52 (8-bit)

Step 1: +52 in binary  +52 = 00110100 Step 2: invert all bits      → 11001011 Step 3: add 1   11001011 +       1 ──────────────  11001100 −52 = 11001100 (two's complement)
11001100
−1286432168421

−128+64+8+4 = −52 ✓

Representing Text

Every character is assigned a binary code using a character set. The two key ones are ASCII and Unicode.

🔤 ASCII

  • 7 bits per character
  • Supports 128 characters (0–127)
  • Covers English letters, digits 0–9, punctuation & control codes
  • Example: 'A' = 65 = 1000001

🌍 Unicode

  • Uses more bits (often 8/16/32 per character)
  • Supports millions of characters
  • All languages, symbols, emojis 😀, maths, etc.
  • Backward-compatible with ASCII

Representing Sound

🎵 Analogue → Digital

Real-world sound is a continuous (analogue) wave. To store it in binary, the wave is sampled — the amplitude is measured at regular intervals and each measurement is converted to a binary value.

📐 Two Key Terms

  • Sample rate — samples taken per second (Hz)
  • Sample resolution — bits used per sample

More samples + more bits per sample = more accurate sound, but larger files.

Sampling: measuring the wave's amplitude at fixed time intervals
1.2 Text, Sound & Images19 / 32
1.2 · Text, Sound & Images

Sample Rate and Resolution

🎚️ Sample Rate

Number of samples per second, measured in Hertz (Hz). CD-quality audio uses 44,100 Hz.

Higher sample rate → more accurate wave → larger file

🎚️ Sample Resolution

Number of bits per sample — determines how many different amplitude levels can be recorded.

Higher resolution → more possible values → better quality, larger file

e.g. 8-bit = 256 levels, 16-bit = 65,536 levels

📊 Low vs High Sample Rate

More samples per second = smoother digital wave = more accurate
Trade-off: higher sample rate & resolution improve quality but increase file size — more bits must be stored.

Representing Images

🖼️ Images = Grids of Pixels

An image is stored as a grid of pixels (picture elements). Each pixel's colour is converted into a binary value.

  • Resolution — total number of pixels (e.g. width × height)
  • Colour depth — bits per pixel (determines how many colours)

🧮 Example

A 4 × 4 image with 1-bit colour depth (2 colours: black/white) needs 16 bits in total — one bit per pixel.

Zoom in far enough and every image is just coloured squares

Resolution and Colour Depth

📏 Resolution

Total number of pixels in the image (width × height).

File size grows with width × height

e.g. 1920 × 1080 = 2,073,600 pixels

🎨 Colour Depth

Number of bits per pixel. Number of possible colours = 2ⁿ (n = bits per pixel).

File Size Calculations — Images

📐 The Formula

File size (bits) = width × height × colour depth

Then convert bits → bytes → KiB → MiB by dividing by 8, then 1024, then 1024.

🔢 Conversion reminder

  • bytes = bits ÷ 8
  • KiB = bytes ÷ 1024
  • MiB = KiB ÷ 1024
Worked Example — full calculation

1024 × 768 image, 24-bit colour

Step 1: number of pixels 1024 × 768 = 786,432 pixels Step 2: file size in bits 786,432 × 24 = 18,874,368 bits Step 3: convert units (÷8, ÷1024, ÷1024) ÷ 8     = 2,359,296 bytes ÷ 1024  = 2,304 KiB ÷ 1024  = 2.25 MiB

The file is about 2.25 MiB (uncompressed)

Show every step — marks are given for correct working even if you slip up at the end.

File Size Calculations — Sound

📐 The Formula

File size (bits) = sample rate × sample resolution × duration (s)

If stereo, multiply by 2 (two channels). If mono, multiply by 1.

🎧 Typical values

  • CD quality: 44,100 Hz, 16-bit, stereo
  • Telephone: 8,000 Hz, 8-bit, mono
Worked Example — full calculation

44,100 Hz · 16-bit · 30 seconds · stereo

Step 1: one channel of audio 44,100 × 16 × 30 = 21,168,000 bits Step 2: stereo = 2 channels 21,168,000 × 2 = 42,336,000 bits Step 3: convert units ÷ 8     = 5,292,000 bytes ÷ 1024  ≈ 5,168 KiB ÷ 1024  ≈ 5.05 MiB

The stereo clip is about 5.05 MiB

Note: a mono version would be half the size — about 2.52 MiB.

Why Compress Data?

📉 Smaller Files = Big Benefits

  • Less storage space needed on devices / servers
  • Less bandwidth used when downloading or streaming
  • Faster transmission — files arrive more quickly
  • More files can fit on a memory card or in an email attachment

⚖ The Trade-Off

Compression has a cost:

  • Lossy compression permanently removes data → lower quality
  • Lossless compression keeps all data → larger than lossy
  • Compression & decompression take processing time
Real example: a 4K video would be gigabytes uncompressed — compression is what makes streaming it possible at all.

Run-Length Encoding (RLE)

🔁 What Is RLE?

Run-length encoding is a lossless compression method. Consecutive identical values ("runs") are replaced with a count + value pair.

Great for images with large blocks of the same colour, or simple graphics.

Remember: RLE is lossless — every pixel can be rebuilt exactly from the encoded form.
Worked Example — RLE

A row of 10 pixels

W W W W W
B B B
W W
W W W W W  B B B   W W // 5 W's, then 3 B's, then 2 W's → 5W 3B 2W

10 characters stored as just 6 → smaller file ✓
